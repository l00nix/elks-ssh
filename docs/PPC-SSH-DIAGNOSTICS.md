# PPC crypto and process diagnostics — 2026-11-05

The physical PPC's stalled SSH worker was spending time in its first X25519
calculation. A separate diagnostic build reached that operation within ten
seconds and had not finished it at the 180-second observation limit. This
establishes slow key exchange; it does not establish successful host verification,
authentication or an out-of-memory failure on the PPC.

Serial is temporary maintenance access only. SSH traffic uses Ethernet and the
server consumes its independently provisioned persistent state. No private key,
state contents or generated bytes are printed by the diagnostics.

## Physical baseline

The original listener was PID 9 and its connection worker PID 11. Serial `ps`
confirmed the worker was CPU-active. The abandoned worker did not stop promptly
with SIGTERM and was force-stopped after its identity was checked. The diagnostic
build then logged fixed operation labels, PID and elapsed whole seconds around
unchanged crypto functions. No authentication checks or timeouts were relaxed.

The Mac negotiated Curve25519, Ed25519 and ChaCha20-Poly1305 and waited for the
key-exchange reply. The operator stopped that diagnostic client after 183 seconds.
The diagnostic processes were removed and the original `/bin/sshtrial` listener
was restored; the persistent-state lock was absent. Startup files were unchanged.

## Faster X25519 and whole-session memory

An isolated build combines the existing, pinned BearSSL m15 X25519 adapter with
the persistent source. Ed25519 remains inherited Dropbear code. The stock ELKS
linker script is retained: the unchanged BearSSL SHA-256 round function is given
an explicit section and far-call declaration to fit both code segments. This
does not change the kernel, libc or architecture.

The ordinary forked server authenticates in QEMU but cannot fork the command
shell: the diagnostic wrapper records errno 12 (`ENOMEM`). The failure occurs
both with and without concurrent `ps` sampling. ELKS `pid_t` is unsigned, so the
diagnostic comparison must use `(pid_t)-1`; a signed `< 0` test missed this error.

A small experimental listener instead forks and executes Dropbear's existing
`-i` mode. It holds only one connection worker at a time, including after
authentication. Protocol handling, authentication and randomness stay in
Dropbear. The listener does not accept executable paths or options from peers.
Its observed process size is 15,760 bytes, allowing the same SSH worker to fork
and execute the shell with its original heap and stack reservations.

| QEMU check | Result |
| --- | --- |
| Eleven SSH session cases | Pass, including exact output, rejected keys/pins/permissions, PTY, EOF and rekey |
| Malformed X25519 inputs | Zero, one and short points rejected; workers reaped |

These are QEMU 486 observations, not original-8088 timings or peak memory bounds.
The launcher's full-session pass does not retroactively validate earlier m15
binaries. The unchanged Ed25519 signing and verification remain significant work
and have unresolved target timing-security concerns. This is an experiment, not
a production service or release candidate.

## Physical faster-worker comparison

After checksums matched, the same QEMU-tested launcher and worker were started
temporarily on the PPC's port 2222. The Mac used the existing pinned host key and
dedicated client key over Ethernet. Serial observed fixed stage labels and
processes only; no entropy helper was present.

Both X25519 operations completed in **93 target seconds each**. Ed25519 signing
then began and was still unfinished at the 305-second observation. The client
was operator-stopped after 308.8 seconds, still waiting for the key-exchange
reply. This is not an observed authentication timeout, verified host signature,
successful login or shell-memory result on hardware. No timeout was increased.

Stopping the launcher removed both it and the busy worker. The state lock was
absent, and the original `/bin/sshtrial` listener was restored as PID 99. The
comparison executables remain staged under `/root`, but are not running; boot
configuration was not replaced. Fresh process identities must be checked before
further maintenance. Neither secret state nor private keys were rolled back.

## Independent Ed25519 performance probe

An isolated probe of Daniel Beer's [c25519 package](https://www.dlbeer.co.nz/oss/c25519.html)
passes the public RFC 8032 empty-message signing vector, verification, an altered
signature and short-signature rejection on the host under sanitizers and in a
medium-model ELKS QEMU build. The linked probe passes the static 8086 audit.
Signing takes two guest seconds, verification seven and altered-signature
rejection six in this run. These are preliminary emulator observations only.

This is **not linked into SSH**. The bridge deliberately accepts only the public
empty-message fixture. Upstream omits the RFC 8032 `S < L` validation; strict
encoding/subgroup behavior, differential vectors, target code and timing all
need review before considering a backend. No real private keys or generated
randomness are used. A faster probe alone does not qualify authentication code.

The unchanged source archive, source hashes, small benchmark bridge and result
are identified in the [probe evidence](evidence/20261105-ppc-crypto-stages/c25519-public-probe/provenance.json).
The harness is the existing `feasibility/src/edbench.c`. Compile it with the
retained bridge and upstream `edsign.c`, `ed25519.c`, `f25519.c`, `fprime.c` and
`sha512.c`, using medium model, `-march=i8086 -mtune=i8086 -Os`, 1 KiB heap and
8 KiB stack. Run the existing `qemu_crypto_integration.py --names edbench` on a
disposable FAT image. The source archive remains a separately downloaded review
artifact rather than a selected project dependency.

## Reproduce

```sh
ELKSSH_ELKS=/path/to/elks ELKSSH_TRACE_X25519=m15 \
  sh experimental/persistent-entropy/build-trace.sh
ELKSSH_ELKS=/path/to/elks sh experimental/persistent-entropy/build-listener.sh
python3 tests/qemu_ssh.py --image /path/to/hd32-minix14.img \
  --filesystem minix --mfs feasibility/build/mfs \
  --server feasibility/build/persistent-trace-m15/sshfast \
  --inetd-launcher feasibility/build/inetd-listener/sshlisten \
  --persistent-entropy --seed-helper feasibility/build/host-seed/seed-record \
  --cpu 486 --suite --session-suite --kex-rejection-suite \
  --out feasibility/test-output/inetd-comparison
```

Omit `ELKSSH_TRACE_X25519` for the unchanged-X25519 diagnostic build. Omit
`--inetd-launcher` to reproduce the ordinary m15 fork failure; add
`--no-memory-sampling` for the quiet comparison. Build scripts only create
artifacts and audits; they never install or start a service.
