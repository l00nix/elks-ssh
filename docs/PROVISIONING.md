# Offline provisioning and recovery experiment — 2026-11-05

The PPC's physical stage 6 recovery and stage 3 refusal tests pass. A stale lock
remains on the disposable PPC image. It must not be cleared just to resume the
old sequence. See the [physical evidence](PERSISTENT-STATE.md).

## Chosen workflow

| Approach | Decision |
| --- | --- |
| Delete the stale lock and resume old state | Reject: uncertain or restored state can repeat output |
| Send a seed using existing Telnet/FTP | Reject for secret material: the laboratory control connection is plaintext |
| Automatically request a seed from a LAN helper | Does not meet independent operation after setup |
| Create fresh per-device material on a trusted host, then install offline | Evaluate: no runtime companion, stopped consumers and explicit recovery |

Initial provisioning and recovery use the same fresh-source operation. The
host-side [bundle creator](../experimental/persistent-entropy/provision.py)
obtains 48 bytes from the host OS random source and sends them through a pipe
to a [native helper](../experimental/persistent-entropy/seed-record.c). The
helper calls the unchanged, pinned BearSSL 0.6 HMAC_DRBG initializer and writes
the existing 1024-byte state format with generation zero. It does not generate
SSH host keys or implement a new DRBG.

The wrapper exclusively creates a new mode-700 directory and mode-600 state
file, validates the record, flushes it and checks readback. A final manifest
records completion without including the seed, record, fingerprint, hostname or
owner's name. Existing destinations and symlinks are refused. Source/helper
failure does not produce an accepted bundle. There is no option to reuse an
old seed, and no recovery option that edits a previous bundle. A failed attempt
must not be used, even if some files remain.

This is **host preparation only**, not an image installer or an SSH-ready
deployment. File flushes on the host do not qualify target media. Run only on a
trusted macOS/Linux installation host with the locally built helper. Core dumps
are disabled, but Python and C stdio do not guarantee erasure of every temporary
memory copy. Keep resulting files outside source repositories and cloud sync.
Do not retain a bootable backup of provisioned state for later reuse or clone
it to another device. Deleted host files are not guaranteed securely erased.

## Installation and recovery contract

The next installer must operate on a separate offline image with all RNG
consumers stopped. It must validate the filesystem and ownership, install fresh
state with private modes, flush and verify it, and only then remove the old
lock. An incomplete operation must remain unusable. Real-media recovery must
not silently force past filesystem damage; preserve the source image and
repair or replace it first. Reboot validation and storage qualification remain
necessary. The discarded image/state must never be restored for SSH use.

The public QEMU recovery harness deliberately uses two different published
48-byte inputs. It exercises initialization, interrupted update/refusal,
offline replacement while the VM is stopped, and continuation across reboot.
This checks sequence separation and format compatibility; public fixtures do
not establish entropy quality. Its use of `mfs -f` is confined to killed,
disposable test images and is not a production filesystem recovery policy.

**Never run `rngprobe` or `persistprobe` against real provisioning material:**
those existing public-fixture probes print generated bytes. A non-disclosing
hardware check and the production SSH adapter are still required.

## Reproduce

Build and test without creating a retained deployment bundle:

```sh
sh experimental/persistent-entropy/build-host-seed.sh feasibility/build/host-seed
ELKSSH_SEED_HELPER=feasibility/build/host-seed/seed-record \
  python3 experimental/persistent-entropy/test_provision.py -v
python3 experimental/persistent-entropy/qemu_recovery.py \
  --image /path/to/hd32-minix14.img --mfs feasibility/build/mfs \
  --probe /path/to/audited/persistprobe \
  --helper feasibility/build/host-seed/seed-record \
  --out feasibility/test-output/provisioning-qemu
```

Host tests use temporary private directories and publish only test outcomes.
All QEMU inputs and serial output are public fixtures. No host-generated secret
bundle has been installed on the PPC or HP. The ELKS probe binary is unchanged;
the new helper is a host program, not an additional 8086 memory requirement.

Results: all **10 host tests** pass, including CLI output handling and refusal
to overwrite a destination. The **five-boot QEMU lifecycle** passes: initial
output, interrupted update, refusal, fresh offline provisioning, and recovery
restart. Both fresh outputs and the full final state match the independent
reference; the input HDD image is unchanged.
